    v1.1 测试计划¶

    本页把 v1.1 需求 的验收矩阵 A01–A21 落到具体测试类与用例。需求只给“验什么”，本页给“怎么验”。

    运行方式¶

    mvn -o test
    • 全部用例离线运行：本地 FakeServer、临时目录、内存仓储；不读真实 Key，不访问外网。
    • 不使用 Thread.sleep 做同步；并发用 CountDownLatch + @Timeout。
    • 每个测试独立创建 server、agent、repository，不共享可变静态状态。
    • 测试类按能力拆分，方法名以 aXX_ 开头，便于对照验收项。

    测试类¶

    类 覆盖
    ClientSseTest 请求形状、SSE 语法、装配、非法响应
    AgentRunTest 基础运行、system、上下文接续
    AgentToolLoopTest 工具循环、工具失败、轮次
    StreamResultTest deltas() 生命周期、完成态、等价性
    CompressionTest 触发、摘要、压缩失败、提交
    RepositoryContractTest load / append / compact 契约
    RetryTest 重试条件、次数、退避、流式边界
    CancelTest 取消语义与再次运行
    ToolTest 工具注册、执行、错误映射
    SchemaTest Schema 生成与拒绝类型
    FileToolTest 读写编辑删除、路径安全、原子写
    ErrorCodeTest HTTP 映射、错误码、消息安全
    ApiSurfaceTest 公共 API 反射检查：不存在已移除的方法
    LoggingTest 日志内容与敏感信息
    CrossCuttingTest 并发、原子提交、文档构建（可选拆分）

    夹具¶

    夹具 作用
    FakeServer 本地 HTTP 服务；按脚本返回 SSE 帧或错误；记录请求次数与请求体
    RecordingTool 记录调用次数与参数；可配置返回结果或抛异常
    RecordingRepository 记录 append / compact 的调用与入参；可配置抛异常
    TestLogs Logback ListAppender，断言日志中不出现敏感串
    @TempDir 文件工具的工作区与临时文件
    StreamRecorder 在测试线程消费 deltas()，收集增量与异常

    FakeServer 必须支持：分块发送、延迟发送、发送到一半断开、返回非 2xx、返回非法 JSON、返回空体。

    用例矩阵¶

    A01 基础运行¶

    AgentRunTest

    用例 断言
    a01_firstRun 返回 content；append 一次；pending 顺序为 user、assistant；usage 正确
    a01_secondRunKeepsContext 第二次请求的 messages 含第一次的 user/assistant，再追加新 user
    a01_systemDefault 未配置 system 时请求不含 system；配置后 system 在最前
    a01_blankContentRejected content 为 null/空白 → 1002，不调用 client，不写仓储

    A02 工具循环¶

    AgentToolLoopTest

    用例 断言
    a02_singleTool 第一轮 tool_calls，执行工具；第二轮 stop；最终 content 正确
    a02_requestRebuilt 第二轮请求包含第一轮的 assistant(tool_calls) 与 tool 结果；不会重复发送第一轮请求
    a02_toolPreambleInContent 第一轮正文“我先读一下”进入 deltas 和最终 content；两者一致
    a02_historyOrder pending 为 user、assistant(tool_calls)、tool、assistant；tool_call_id 对应
    a02_multipleToolsInOrder 两个 tool_calls 按数组顺序执行，tool 消息顺序一致
    a02_reasoningPreserved assistant 的 reasoning_content 进入历史

    A03 工具失败¶

    AgentToolLoopTest

    用例 断言
    a03_toolThrows 抛对应 TOOL_*；后续工具未执行；append/compact 未调用
    a03_unknownTool 未注册工具 → 4001；本次不提交
    a03_lumiRoseExceptionPassthrough 工具抛出的 LumiRoseException 原样透传，不被包装

    A04 轮次上限¶

    AgentToolLoopTest

    用例 断言
    a04_turnLimit 每轮都返回 tool_calls；请求次数恰为 maxTurns；抛 3001；仓储未写
    a04_maxTurnsOne maxTurns=1 时只请求一次

    A05 SSE 与请求形状¶

    ClientSseTest

    用例 断言
    a05_requestShape URL、方法、Authorization、Content-Type、Accept、stream: true、tools、max_tokens 符合 R02
    a05_contentAndReasoning 多个 delta.content / reasoning_content 拼接正确
    a05_toolCallFragments 首片 id/type/name，后续片 arguments 拼接；同 index 合并
    a05_usageLastWins 多个 usage 取最后一个
    a05_multilineData 同一事件多行 data: 用 \n 拼接；\r 去掉；注释与 event: 忽略
    a05_doneTerminates [DONE] 后停止读取；EOF 前有 finish_reason 正常返回
    a05_invalidJson 非法 JSON → 2002，cause 不保留
    a05_emptyChoices choices 为空 → 2002
    a05_missingFinishReason EOF 仍无 finish_reason → 2002
    a05_toolCallConflict 同 index 的 id/name 冲突 → 2002

    A06 流式消费¶

    StreamResultTest

    用例 断言
    a06_lazyStart streamRun 返回后未发请求；首次迭代 deltas() 才发
    a06_orderAndContent 增量按到达顺序；拼接等于最终 content
    a06_pendingAccessThrows 未消费时 content() / usage 抛 IllegalStateException
    a06_afterComplete 迭代结束后 content/usage 可用；deltas() 再消费为空
    a06_singleConsumer 第二次迭代 deltas() 抛 IllegalStateException
    a06_deltasOnlyContent reasoning 与工具事件不出现；工具轮正文可出现于增量

    A07 流式等价¶

    StreamResultTest

    用例 断言
    a07_runEqualsStream 同一 SSE 脚本下 content、pending 历史、usage 一致
    a07_runDeltasEmpty run 的 deltas() 为空
    a07_sameErrorCode 同一失败脚本下两者错误码一致

    A08 取消¶

    CancelTest

    用例 断言
    a08_cancelMidStream 消费到第 N 个增量后 cancel()；后续无增量；抛 3004
    a08_cancelIdempotent 多次 cancel() 无异常
    a08_noCommit 取消后 append/compact 未调用
    a08_rerunAfterCancel 同一会话再次 run 成功
    a08_cancelDuringBackoff 退避期间取消 → 3004，不继续请求
    a08_toolSideEffectKept 工具已执行后取消，副作用不回滚，历史不写

    A09 重试¶

    RetryTest

    用例 断言
    a09_retry500ThenSuccess 第一次 500、第二次成功；请求 2 次
    a09_retry429ThenSuccess 429 可重试
    a09_noRetry401 401 只请求一次，抛 2001
    a09_exhausted 始终 500 时请求 1 + maxRetries 次，抛最后一次异常
    a09_noToolReplay 工具执行后网络失败重试，工具只执行一次
    a09_retryNotCountedAsTurn 重试不增加 maxTurns 计数

    退避基数设为 1ms，只断言请求次数与顺序，不断言墙钟时间。

    A10 流式重试边界¶

    RetryTest

    用例 断言
    a10_retryBeforeFirstDelta 首个正文增量前断流 → 重试并成功
    a10_noRetryAfterDelta 已交付增量后断流 → 不重试，抛 2003
    a10_noRetryAfterFinishReason 已收到 finish_reason 后异常 → 不重试

    A11 压缩触发¶

    CompressionTest

    用例 断言
    a11_triggersAboveThreshold contextTokens > window × threshold 时发压缩请求
    a11_summaryMaxDerived window=4000、threshold=0.65 时压缩请求的 max_tokens=980；大窗口封顶 2048
    a11_summarySaved compact 一次；summary 为 assistant 且带 header；旧消息 active=false
    a11_requestAfterCompression 本次对话请求为 [system?] + [summary] + [user]
    a11_contextTokensUpdated 新 contextTokens 为最后一次成功响应的 usage.total_tokens
    a11_recompress 第二次压缩时旧摘要也被置为 inactive

    A12 不压缩¶

    CompressionTest

    用例 断言
    a12_belowThreshold 未超阈值不发压缩请求，append 正常
    a12_windowNull contextWindowTokens=null 时永不压缩
    a12_equalThreshold 等于阈值不压缩（严格大于才触发）

    A13 压缩失败¶

    CompressionTest

    用例 断言
    a13_compressionHttpError 压缩请求失败 → 3005；append/compact 未调用
    a13_emptySummary 摘要空白 → 3005
    a13_truncatedSummary 压缩 finish_reason=length → 3005
    a13_missingUsageAfterCompression 压缩后最终响应无 usage → 3005；不写
    a13_oldHistoryIntact 失败后 load 结果与运行前一致
    a13_nextRunRetriesCompression 下次 run 重新判断并再次尝试压缩

    A14 原子提交¶

    CompressionTest + AgentRunTest

    用例 断言
    a14_compactOnce 压缩成功的 run 只调用一次 compact，入参含 summary、pending、contextTokens
    a14_appendOnlyPending 普通 run 只调用 append，不调用 compact
    a14_failureNoWrite 压缩后对话失败 → 不写；旧历史不变
    a14_repositoryThrows append/compact 抛异常 → 5001

    A15 仓储契约¶

    RepositoryContractTest

    对内存实现运行同一组契约用例；未来 JDBC 实现复用。

    用例 断言
    a15_loadEmpty 不存在 → Conversation.empty(id)，非 null
    a15_loadOnlyActiveSorted 只返回 active，按 id 升序
    a15_appendKeepsActive append 后旧 active 不变，只多出 pending
    a15_firstAppendCreatesConversation 空仓储首次 append 创建 conversations 行；load 能读到消息与 contextTokens
    a15_firstCompactCreatesConversation 空仓储首次 compact 创建 conversations 行并写入 summary
    a15_emptyAppendNoop append 空列表不创建行、不报错
    a15_compactDeactivates compact 后旧 active 全为 false，summary 与 pending 为 true
    a15_toolCallsAttached tool calls 按 message_id + call_index 挂到 assistant
    a15_inactiveToolCallsSkipped 非 active 消息的 tool calls 不加载
    a15_contextTokensUpdated 两种写操作都更新 contextTokens
    a15_immutableSnapshot load 返回值不可变，外部修改不影响存储
    a15_concurrentWrites 多线程写不同会话无数据竞争；同一会话写入不破坏结构

    A16 并发模型¶

    用例 断言

    不做的测试¶

    • 真实 DeepSeek 调用、真实网络抖动、代理/CDN 缓冲。
    • 120s 读超时的真实等待；由 FakeServer 断连覆盖。
    • 跨进程并发、JDBC 实现、Micrometer/OpenTelemetry。
    • 性能、压力、长时间稳定性；本版不设性能指标。
    • 压缩摘要质量的语义评分；只验证结构、触发与失败语义。

    完成标准¶

    1. A01–A21 每条至少一个自动化用例通过（A21 与代码审查项可用脚本/人工检查）。
    2. mvn -o test 全绿，且不依赖执行顺序。
    3. 失败用例的断言指向可观察行为，不依赖私有实现。
    4. 需求变更时，先改 v1.1 需求，再同步本页与测试。
